# 개발 기록

## 2026-09-15 (4) — 드롭 아이템 아이콘

나무위키 각 보스 문서 "주요 보상" 항목에서 아이템 아이콘을 수집했다. 주간 보스 25종, 아이템 80개(76KB).

- **이름은 alt 가 아니라 카드 텍스트.** `alt` 는 나무위키 파일명(`eqp 모자 루타비스 피에르 …`)이라 잘린 채로 들어온다. 실제 이름은 카드 div 안 `<br>이름</div>` 텍스트다.
- **마지막 카드 함정.** 구간을 카드 마커로 `split` 하면 마지막 조각에 뒤쪽 HTML 이 통째로 붙는다. `lastIndexOf("<br")` 로 이름을 찾으면 엉뚱한 곳을 집어 가디언 엔젤 슬라임이 통째로 누락됐다. `<br>텍스트</div>` 첫 매치로 바꿔 해결.
- **표시는 두 소스를 합친다.** 난이도별 세트 아이템(`boss_drops.json`)을 먼저, 겹치지 않는 주요 보상을 뒤에. 금별 보스는 세트 데이터가 "에테르넬 조각" 수준이라 namu 쪽 고유 아이템(뒤엉킨 흉수의 고리, 카링로이드)이 있어야 쓸모 있다.
- **표기 차이는 퍼지 매칭으로.** `컴플리트 언더 컨트롤`/`컴플리트 언더컨트롤`, `미트라의 분노`/`미트라의 분노 선택 상자` 같은 차이를 공백 제거 + 부분 일치로 흡수한다. 데이터를 손대지 않고 아이콘이 붙는다.
- 일간·월간 난이도 행에는 주요 보상을 붙이지 않는다. 수집 대상이 주간 보스뿐이라 보스 전체 보상을 일간 행에 붙이면 잘못된 인상을 준다.

## 2026-09-15 (3) — 티어표 드롭 아이템 · 아이콘 화질

- **드롭 아이템 표시.** 티어표 각 보스 카드에 드롭을 붙였다. 드롭이 있는 카드는 `flex-1` 로 늘어나 비어 있던 우측 공간을 채운다. 세트별 색(여명 amber / 칠흑 violet / 에테르넬 yellow).
- **출처 문제.** 넥슨 공식 "보스별 주요 보상" 가이드는 302 로 삭제된 상태였다. 나무위키 여명·칠흑·에테르넬 세트 문서에서 확인된 것만 넣고, 하위 일간 보스는 **비워 뒀다** — 근거 없이 채우면 틀린 정보가 그대로 화면에 남는다.
- **데이터 검증을 테스트로.** `drops.test.ts` 가 드롭 키가 가격표·티어표에 실재하는지 본다. 이 테스트가 실제로 `시즌 보스 메이린 normal`(티어 없음) 오타성 항목을 잡아냈다.
- **아이콘 화질.** 원본이 160×153 인데 `image-rendering: pixelated` 를 걸어 뒀던 게 문제였다. 이건 픽셀아트 *확대*용이라 축소에 쓰면 nearest-neighbor 로 픽셀을 버려 계단현상이 생긴다. 제거하니 바로 좋아졌다. 아이콘은 64 → 72px.
- 더 키우려면 소스 해상도가 한계다. CSS 80px 까지는 2배 DPI 에서도 선명하고, 그 이상은 maplestory.io 몹 아이콘(496×504)이 있지만 장당 220KB·33장 7MB 라 webp 변환 없이는 못 쓴다.

## 2026-09-15 (2) — 난이도 배지 · 티어 별 색상화

표기를 컴포넌트 한 벌로 모았다. 같은 정보가 화면마다 다른 모양으로 나오던 걸 정리.

- **난이도 배지 통일.** `DifficultyBadge` 하나로 모든 난이도 표시를 대체했다. 선택 버튼은 같은 배지의 `DifficultyButton` 변형이라 눌린 상태(솔리드 + 링)와 평상시가 한눈에 구분된다. 보스 클리어표·파티 카드·모집글·플래너의 `hard` 같은 영문 노출도 전부 배지로 교체.
- **등급 이름 제거.** `금★5` 처럼 쓰던 표기에서 등급 글자를 빼고 **별 색**으로만 구분한다(`TierStars`). 티어표는 등급별 4개 섹션을 없애고 rank 내림차순 한 표로 합쳤다 — 섹션 제목에 쓰던 "금별/은별/…" 자체가 사라졌기 때문.
- **색을 못 쓰는 자리.** `<select><option>` 과 `title` 속성은 색이 안 먹어서 `tierLabel()` 이 `🟡★★★★★` 처럼 원형 이모지로 등급을 대신한다.
- **아이콘 확대.** 기본 36 → 48px. 티어표 26 → 44, 가격표 28 → 40, 보스 클리어표 22 → 34, 플래너 26 → 36. 아이콘 옆에 난이도 배지를 따로 두는 자리에서는 아이콘 모서리 배지를 끈다(`showDiff={false}`) — 같은 정보가 두 번 나오지 않게.

## 2026-09-15 — 갈 보스 설정 + 보스 아이콘

캐릭터 상세(`/me/characters/[ocid]`)에서 이번 주 갈 보스를 직접 고르게 했다. 보스별 난이도 버튼을 눌러 선택하고, 선택한 보스는 아이콘 + 약칭(`하세렌`) + 실수령으로 표시된다.

- **저장소를 플래너와 공유.** 새 테이블을 만들지 않고 `plan_configs.characters[ocid].bosses` 를 그대로 쓴다. 캐릭터 상세와 플래너가 항상 같은 값을 본다. 단건 수정을 위해 `loadCharConfig` / `patchCharConfig` 추가.
- **검증 일원화.** `validateBossSelection()` 순수 함수로 빼서 액션과 테스트가 같은 규칙을 쓴다 (주간 결정만 · 보스당 난이도 1개 · 인원 1~6).
- **auto 기본값.** 처음 지정할 때만 `auto` 를 끈다. 이미 플래너에서 켜 둔 값은 덮어쓰지 않는다.
- **아이콘.** 나무위키 보스 문서 상단 목록에서 33개를 받아 `public/bosses` 로 자체 호스팅. 지연 로딩이라 `data-src` 를 읽어야 했고 속성이 작은따옴표였다. 런타임 외부 요청은 없다. 원저작권은 넥슨 — 재배포 책임은 배포자에게.
- **폴백 우선 설계.** `BossIcon` 은 파일이 없으면 난이도 색 + 약칭 배지로 자동 대체된다. 아이콘을 빼도 기능이 멀쩡하다.
- 캐릭터 대시보드: 이미지 확대(112px), Lv.260 미만 기본 숨김(`?all=1` 로 전체). 넥슨 캐릭터 이미지는 300×300 중 실제 캐릭터가 약 110×85 뿐이라 `CharacterAvatar` 가 중심을 잘라 보여준다.

검증: vitest 40개, `scripts/check-bossplan.ts` 로 실 DB 복사본에서 저장→재읽기→플래너 반영까지 확인.

### 넥슨 Open API 실측으로 확인한 사실
- `/character/list`, `/scheduler/character-state` 는 키 소유 계정 캐릭터만 조회 가능. 타 계정은 `400 OPENAPI00004`.
- 스케줄러 `date` 는 어제~13일 전만. 기록 없는 날도 `OPENAPI00004`. 월드 리프 시 ocid 가 바뀌어 이력 단절.
- `boss_contents` 행 목록은 가변(등록 상태에 따라 56→80행). `registration_flag` 와 `complete_flag` 는 행 단위로 독립 — 하드 클리어 후 노말로 등록을 바꿔도 하드 행의 완료가 유지됨. 수익·상한 판정은 `complete_flag` 만 사용.
- `quest_state` 는 `"0"/"1"/"2"` 문자열 (미완료/진행중/완료 추정).
- 결정 판매가는 파티 인원수로 나뉨(N인격 = 솔로가 ÷ N). 2026-09-17 패치로 가격 하향(검은 마법사는 10-01), 캐릭터당 결정 **판매** 12개 제한은 삭제됐지만 보스 **입장** 12회 제한은 유지.
- 넥슨 Open ID 로그인은 파트너스 전용 → Discord OAuth + 유저별 API 키 등록으로 시작.

### 결정
- 클리어 가능 판정은 가격이 아니라 나무위키 보스 티어(금/은/동/납 × 별) 기준. 가격 모델은 익스트림을 예외 처리해야 했음.
- 배분 알고리즘: (캐릭터·보스) ⊂ 캐릭터 ⊂ 월드 의 중첩 제약이라 실수령 내림차순 그리디가 최적.
